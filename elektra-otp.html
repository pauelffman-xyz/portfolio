Elektra × SukuPay · UX writing
UX writing case study
One word in the CTA
can cost you the conversion.

In Elektra's login (powered by SukuPay), the button to confirm the verification code said the same thing as the button to request it. A single string for two different actions, and a silent doubt at the most critical step of onboarding.

Client
Elektra México
Product
OTP verification · Login
Role
Product Design · UX Writing
Platform
powered by SukuPay
The context
A remittance flow,
with SMS verification.

Elektra sends money from the US to Mexico and uses SukuPay's infrastructure for its login: phone number → 6-digit code by SMS → access. It's the first real point of friction in the product. Before this step, the user doesn't trust the app yet.

The finding
The same text, for two
completely different actions.

The CTA "Enviar código" ("Send code" in Spanish) appeared twice in the same flow. The first time, it asks for a code to be sent to you. The second time, on the very next screen, it is used to confirm the code you already typed. The user reads "código" in the title, on the button and in the resend link. Nothing tells them which of the three does what.

Why this profile matters: Lucas represents the users who make 1 or 2 transfers and don't come back. They don't need a big reason to leave. A 2-second doubt in front of a button is exactly the kind of friction that pushes them to close the app.
The solution
Split the verb by intent,
don't reuse it for convenience.

"Enviar" (send) stayed only where the real action is sending. On the verification screen, the CTA now names what the button actually does: "Verificar código" (Verify code). The screens below show the product's original Spanish copy.

Why it matters
It's a one-word change,
at the step with the highest drop-off.
01
Less doubt before tapping the button
The user no longer has to decide whether "Enviar código" means requesting a new SMS or confirming the code they typed.
02
Fewer unnecessary OTP resends
A user in doubt tends to tap the resend link "just in case", which triggers an SMS nobody needed.
03
Consistency at a step with low tolerance for error
It's the first real contact with the product. Every ambiguous word there costs more than on any other screen.
Honest note: this change came out of a copy audit plus real support tickets, not from an A/B test run in production. The logical next step is to measure the completion rate of the OTP step before and after the change.
